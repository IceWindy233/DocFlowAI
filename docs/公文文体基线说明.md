# 公文文体基线说明

## 1. 这一层解决什么

撰写与审核提示词里原本写着「句子别太长」「少用并列」「力度词要克制」这类要求。这种约束无法验证，
也无法回归：换一次模型、改一句提示词，都不知道行文节奏是变好还是变坏。

文体基线把这些定性要求换成可对照项：句长、并列密度、力度词配额、层次结构、标点纪律，全部从本机
语料实测出 p25/中位/p75 区间，写入运行配置的 `writing_style.baselines`。撰写侧据此输出文体对照，
审核侧据此给出确定性提示；标点与占位符纪律不依赖区间，本身就是确定性规则。

## 2. 度量指标

指标键与 `StyleMetric` 一一对应，统计前先剥掉 Markdown 装饰，表格与引用块不参与度量。

| 指标键 | 含义 | 统计口径 |
| --- | --- | --- |
| `chars` | 正文字数 | 剥掉装饰与表格、引用块后按字符计 |
| `sentence_length` | 平均句长 | 以 `。！？；` 切句，短于 4 字的碎片不计入 |
| `max_line_length` | 最长自然段字符数 | 按行统计；长行提示阈值取该文种此项的 p75 |
| `dun_per_mille` | 顿号千字密度 | 顿号数 ÷ 正文字数 × 1000，用于量并列密度 |
| `mandatory_words` | 强制词次数 | 应当/必须/不得/严禁；引号内内容已剔除；「不得不」是「只能」义，不计入 |
| `requirement_words` | 要求词次数 | 要/切实/确保/务必；引号内内容已剔除 |
| `suggestion_words` | 建议词次数 | 建议/可以/鼓励/支持；引号内内容已剔除 |
| `percent_values` | 百分数个数 | 占位符里的百分号不是真实数据，不计入 |
| `dashes` | 破折号次数 | 统计 `——`；条数上限由 `max_dashes` 控制，不进区间 |
| `heading_level1` | 一级层次条数 | 「一、」式 |
| `heading_level2` | 二级层次条数 | 「（一）」式 |
| `heading_level3` | 三级层次条数 | 「1.」式 |

度量同时给出几项不入区间的确定性信号：非引语冒号（引语引入、主送机关、层次标题这三种合法位置已
白名单排除）、ASCII 直引号、元评论词、忌用词及其改法。机关行文不出现口语化元评论，因此这一类直接
按禁止处理，不设配额。

## 3. 生成基线

```bash
cd backend

# 先看数值，不落库
uv run docflow style-baseline --source-root "$CORPUS_ROOT" --document-type REQUEST

# 导出 JSON 备查
uv run docflow style-baseline --source-root "$CORPUS_ROOT" --document-type REQUEST \
  --output ../data/reports/style-baseline-request.json

# 确认无误后写入运行配置的 writing_style.baselines
uv run docflow style-baseline --source-root "$CORPUS_ROOT" --document-type LETTER --apply
```

`--source-root` 是本机语料目录，递归收集 `.doc/.docx/.txt/.md`，跳过 `~$` 开头的 Office 临时文件
与空白模版；`.doc/.docx` 优先用 macOS 自带 `textutil` 转文本，不可用时退到 LibreOffice；篇幅过短的
扫描产物与空页按最小字数丢弃，单篇转换失败只记入跳过数，不中断整批统计。

同一份公文常同时存在多种格式，附件、协议正本和空白模版也混在同一目录树里，计入会污染该文种区间。
用 `--pattern` 限定格式、`--exclude` 按路径片段剔除，两者都可重复：

```bash
uv run docflow style-baseline --source-root "$CORPUS_ROOT" --document-type REQUEST \
  --pattern '*.doc' --exclude 附件 --exclude 协议 --exclude 模版
```

先不加 `--apply` 跑一遍，核对样本数与预期篇数是否吻合；数量明显偏多通常意味着同一篇被多种格式重复
统计，或非本文种材料被收进来了。

`--document-type` 只接受 `REQUEST` 与 `LETTER`，与 `DraftRequirements.document_type` 同键。
`--apply` 会新建一个配置版本，配置不可变且可回滚，`source_label` 记住样本规模，便于日后回溯基线来源。

## 4. 存放约定

- 统计逻辑进仓库：`backend/src/docflow/services/style_baseline.py` 与 `docflow style-baseline` 子命令。
- 数值只进数据库：`writing_style.baselines`，随配置版本留痕。逐字原文不落地，命令输出只有区间与样本数。
- 语料目录只留在本机，已列入 `scripts/check-public-repo.sh` 的禁止跟踪清单；导出的 JSON 放
  `data/reports`，该目录同样不进 Git。
- 换一批语料重跑即可更新基线，不需要分发任何样本文件。

## 5. 判定口径

区间偏离只作提示，不参与 `passed` 判定。唯一的硬门禁是未补齐的占位符：占位符是事实缺口，不是风格差异。

不拿中位数当合格线，是因为真实公文的个体离散度极大。同一文种里，短篇一事一议和长篇多事项并列都
合规，字数、句长、层次条数天然分散，用中位数卡线会把大量合规稿判成问题稿。有意义的信号是多项同向
偏离——句长、顿号密度、层次条数同时偏高，说明整篇节奏不对；单项落在区间外不等于错。

长行提示同理：阈值取该文种 `max_line_length` 的 p75，没有基线时才退回配置项 `long_line_fallback`。
固定字数阈值在真实公文上误报严重，长段落是文种常态，不是缺陷。

## 6. 占位符三类

缺失事实一律占位，不得杜撰。

| 占位符 | 用途 | 是否阻断定稿 |
| --- | --- | --- |
| `【待补：xx】` | 缺具体数字、文号、人名、日期 | 阻断 |
| `【示意·待核】` | 给了参考量级，等待核对 | 阻断 |
| `【待核对原文】` | 引用表述拿不准，需回原文核对 | 不阻断 |

阻断由 `placeholder_export_gate` 控制，默认开启：带着待补数字或示意量级定稿，比行文风格问题严重得多。
