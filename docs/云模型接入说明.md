# DocFlow AI 云模型接入说明

## 1. 能力与供应商分工

| 能力 | 供应商 | 模型 | 调用阶段 |
| --- | --- | --- | --- |
| 文本 Embedding | 阿里云百炼 | `qwen3.7-text-embedding`，2560 维 | 离线 Chunk 入库、在线问题向量化 |
| 候选重排序 | 阿里云百炼 | `qwen3-rerank` | RRF 后、答案生成前 |
| RAG、审核与撰写生成 | 任意 OpenAI 兼容服务 | 模型档案指定；出厂默认示例为硅基流动 `deepseek-ai/DeepSeek-V4-Flash` | LangGraph 内容生成节点 |
| 复杂页面增强 | 阿里云百炼，可选 | 配置中心中的 VLM 档案 | 本地解析质量不足的页面 |
| 页面视觉向量 | 本地 | `vidore/colqwen2.5-v0.2` | 离线页面入库、在线视觉查询 |

内容生成统一走通用 `openai_compatible` 协议适配器：Base URL、模型名、密钥变量和“请求扩展参数”
全部来自配置中心的“云端对话模型（OpenAI 兼容）”档案。出厂默认档案预填硅基流动示例值，Base URL 为
`https://api.siliconflow.cn/v1`，模型为 `deepseek-ai/DeepSeek-V4-Flash`，并带 `enable_thinking=false`
以使用非思考模式。系统要求模型只依据候选证据输出答案，并使用 `[证据编号]` 标注来源；生成结果会再次
校验证据编号和 `page_id`，引用异常时降级到本地抽取式回答。

“请求扩展参数”用于承载非思考模式一类的供应商专有开关，只接受字符串、数字和布尔标量，且不能覆盖
`model`、`messages`、`stream`、`response_format`、`temperature`、`max_tokens` 这些核心字段。切换
其他 OpenAI 兼容供应商时，只需在档案中修改 Base URL、模型名和密钥值：密钥变量名保持
`CHAT_LLM_API_KEY`，配置中心的密钥白名单和模型网关代码都不需要改动。

## 2. 密钥注入

复制根目录 `.env.example` 为 `.env`，只填写等号右侧：

```dotenv
DASHSCOPE_API_KEY=
CHAT_LLM_API_KEY=
```

`.env` 已被 Git 忽略。后端启动时将它加载到进程环境，但数据库只保存
`DASHSCOPE_API_KEY`、`CHAT_LLM_API_KEY` 这两个变量名称。API 和 Web 只返回“已配置/未配置”。
升级操作：把 `.env` 中内容生成模型的密钥变量名改为 `CHAT_LLM_API_KEY`，然后重启后端与 Celery
Worker；数据库中的历史配置版本由 Alembic 迁移自动改写，不需要在配置中心手工调整。

更新 `.env` 后必须重启后端；百炼 Embedding 由 Celery Worker 执行，因此 Worker 也必须重启。

`qwen3.7-text-embedding` 使用百炼工作空间专属 OpenAI 兼容地址。还需要从百炼控制台取得
Workspace ID，并在配置中心“百炼文本向量”档案的“百炼 Workspace ID”字段中填写。后端会
自动生成只读的派生 Base URL：

```text
https://<WorkspaceId>.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
```

`qwen3-rerank` 复用同一个 Workspace ID，并自动派生：

```text
https://<WorkspaceId>.cn-beijing.maas.aliyuncs.com/compatible-api/v1
```

Workspace ID 不是密钥，可以保存在不可变配置快照中。用户不需要再手工拼接 Base URL。
系统会拒绝探测或启用缺少 Workspace ID 的百炼文本向量路由。

## 3. 配置中心启用顺序

1. 在“模型档案”中选择“百炼文本向量”，填写 Workspace ID；Base URL 会自动生成。
2. 分别选择“百炼文本向量”“百炼 Qwen3 轻量重排序”和“云端对话模型（OpenAI 兼容）”，确认页面显示“密钥已配置”，
   再点击“连通性测试”。探测直接使用当前表单草稿，会发送最小的真实
   Embedding/Chat 请求，并验证 2560 维向量或非空模型响应，不以 `/models` 可访问代替能力验证。
3. 打开三个模型的“启用模型”开关。
4. 在“能力路由”中设置：
   - 文本向量（百炼）：`bailian_embedding`；
   - 轻量重排序（百炼）：`bailian_reranker`；
   - 内容生成（OpenAI 兼容）：`cloud_chat_llm`。
5. 在“执行与预算”中开启云端处理，并设置单任务调用、Token 和费用上限。
6. 保存配置。文本 Embedding 会触发 `REINDEX_REQUIRED`，当前已发布索引不会被污染。
7. 创建新的 M1 入库任务，勾选允许云端处理；先使用少量代表性文件估算调用量。
8. 入库成功后校验并发布新的索引代际，再进入“知识问答”执行端到端测试。

## 4. 实际检索链路

```text
用户问题
├── PostgreSQL BM25/中文 Bigram               本地
├── 百炼 Query Embedding → Qdrant Dense Search 云端编码、本地检索
└── ColPali Query Encoding → Qdrant MaxSim     本地
                    ↓
                 RRF 融合
                    ↓
            百炼 Qwen3 Rerank
                    ↓
    OpenAI 兼容对话模型生成带引用答案
                    ↓
          LangGraph 引用一致性校验
```

若百炼查询向量临时失败，混合检索保留 BM25 和 ColPali 结果；若 Reranker 调用失败，保留 RRF
顺序；若对话模型调用失败，生成节点降级为 `LOCAL_EXTRACTIVE`，并在 Web 显示降级原因。每次问答
记录云调用次数和输入/输出 Token。

## 5. Publication 约束

- Embedding 模型签名或维度变化必须建立新 Collection；
- 2560 维向量不得与其他维度写入同一 Collection；
- 启用文本 Embedding 后，所有待发布 Chunk 必须为 `READY`；
- 任何 `FAILED` 或未生成文本向量的 Chunk 都会阻止 Publication；
- Publication 会读取 Qdrant Collection 的实际点数和向量维度；文本点数必须等于 Chunk 数，
  视觉点数必须等于 `visual_status=READY` 的页面数；
- 内容生成模型变化不要求重建索引，只影响新的问答、审核与撰写运行。
- Reranker 变化也是 `HOT` 更新，不改变索引向量空间。

## 6. 验证建议

公开仓库不附带真实源文件、云端调用记录或私有 Publication。建议使用
`examples/demo-corpus` 验证以下链路：

- 受支持文件全部进入明确终态，失败、跳过和不支持格式均可追踪；
- Chunk 数与 Qdrant 文本向量点数一致；
- 需要视觉索引的页面数与 ColPali 多向量点数一致；
- 端到端问答能够同时展示词法、文本向量和视觉召回来源；
- 生成模型输出的引用通过 `page_id` 一致性校验；
- 云端调用次数、Token 和估算费用可在工作流运行详情中追溯。

开发阶段的真实成本与质量报告保留在本机 `data/reports`，不会提交 Git。
