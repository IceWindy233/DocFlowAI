# DocFlow AI 系统架构图

本文档描述当前仓库已经实现的 M0–M4 MVP 架构。重点是两条主线：

1. 离线将异构公文转化为结构化文本、页面图和双路向量索引；
2. 在线通过可追溯检索，为知识问答、公文审核和公文撰写提供证据。

以便使用本机 MPS。FastAPI、Web 和基础设施端口均绑定本机地址。

## 2. M0–M1 离线解析与知识入库

~~~mermaid
flowchart LR
    SRC["一个或多个数据源目录"] --> INV["M0 文件盘点"]
    INV --> META["MIME / 扩展名 / 大小 / SHA-256<br/>来源路径 / 案件目录"]
    META --> CLASSIFY{"文件终态"}
    CLASSIFY -->|临时文件| SKIP["SKIPPED"]
    CLASSIFY -->|不支持或容器| UNSUP["UNSUPPORTED"]
    CLASSIFY -->|精确重复| DEDUP["复用重型解析<br/>保留来源关系"]
    CLASSIFY -->|可解析| ADAPTER{"格式适配"}

    ADAPTER -->|DOC / WPS / XLS| CONVERT["LibreOffice 转换"]
    ADAPTER -->|DOCX / XLSX / 图片| NATIVE["原生适配器"]
    ADAPTER -->|PDF| DOCLING["Docling / PDF 原生解析"]
    CONVERT --> UNIFIED
    NATIVE --> UNIFIED
    DOCLING --> UNIFIED["统一 Document JSON<br/>页面 / 段落 / 标题 / 表格 / 坐标"]

    UNIFIED --> QUALITY{"页面质量路由"}
    QUALITY -->|文本充分| STRUCTURED["结构化结果"]
    QUALITY -->|扫描或低文本密度| OCR["本地 OCR"]
    QUALITY -->|局部低质量| REGION["区域重识别"]
    QUALITY -->|复杂表格或图文页| VLM["可选 VLM 增强"]
    OCR --> STRUCTURED
    REGION --> STRUCTURED
    VLM --> STRUCTURED

    STRUCTURED --> TABLE["表格四件套<br/>单元格 JSON / HTML<br/>行语义文本 / 区域截图"]
    STRUCTURED --> PAGE["页面图与 page_id 对齐"]
    STRUCTURED --> CHUNK["标题 / 段落 / 表格语义切块"]

    CHUNK --> LEXICAL[("PostgreSQL Chunk<br/>中文词法检索")]
    CHUNK --> EMBED["可选文本 Embedding"]
    EMBED --> TEXTVEC[("Qdrant 文本向量")]

    PAGE --> COMPLEX{"需要视觉检索？"}
    COMPLEX -->|是| COL["ColPali 页面多向量"]
    COL --> VISVEC[("Qdrant 视觉向量")]
    COMPLEX -->|否| DONE["文本索引就绪"]

    TABLE --> STORE[("本地产物存储")]
    PAGE --> STORE
    DONE --> VALIDATE["Publication 完整性校验"]
    TEXTVEC --> VALIDATE
    VISVEC --> VALIDATE
    VALIDATE --> PUBLISH["原子发布索引代际"]
~~~

每份表格、页面图、Chunk 和向量都通过稳定的 <code>document_id/page_id</code> 对齐。
被判定为必需视觉索引的页面若 ColPali 失败，只能重试或进入人工审核，不能伪装为成功。

## 3. M2 在线混合检索与问答

~~~mermaid
flowchart LR
    QUERY["用户问题"] --> UNDERSTAND["问题理解与查询改写"]
    UNDERSTAND --> LEX["中文词法召回<br/>字符 bigram / BM25 风格"]
    UNDERSTAND --> SEM["文本向量召回<br/>可选百炼 Embedding"]
    UNDERSTAND --> VIS["视觉召回<br/>ColPali Query 多向量"]

    LEX --> FUSION["RRF 融合"]
    SEM --> FUSION
    VIS --> FUSION
    FUSION --> DIVERSITY["页级与文档级多样化"]
    DIVERSITY --> RERANK["可选百炼 Reranker"]
    RERANK --> EVIDENCE{"证据充分？"}

    EVIDENCE -->|否| REFUSE["安全拒答"]
    EVIDENCE -->|是，结构化问题| EXTRACT["本地确定性抽取<br/>金额 / 人员 / 多部门汇总"]
    EVIDENCE -->|是，开放问题| GENERATE["DeepSeek 证据约束生成"]
    EXTRACT --> VERIFY["引用一致性校验"]
    GENERATE --> VERIFY
    VERIFY --> ANSWER["答案 + 页码引用<br/>候选证据 + 工作流轨迹"]
~~~

三路检索相互独立：任一云端或视觉分支失败时，系统保留可用分支并记录警告。多部门回复等
结构化聚合优先使用可复现的本地抽取；开放问题才进入生成模型。

## 4. M2–M4 Agent 状态图

~~~mermaid

    end

    subgraph REVIEW["公文审核 Agent"]
        R1["读取正文与审核范围"] --> R2["确定性规则检查"]
        R1 --> R3["检索参考材料"]
        R2 --> R4["DeepSeek 语义审核"]
        R3 --> R4
        R4 --> R5["类别归一 / 同义意见合并"]
        R5 --> R6["人工接受或驳回"]
        R6 --> R7["应用安全修改 / 导出报告"]
    end

    subgraph DRAFT["公文撰写 Agent"]
        D1["需求门禁"] --> D2{"字段完整？"}
        D2 -->|否| D3["返回缺失字段"]
        D2 -->|是| D4["检索历史案例"]
        D4 --> D5["区分事实证据与风格参考"]
        D5 --> D6["生成提纲"]
        D6 --> D7["人工确认提纲"]
        D7 --> D8["生成初稿"]
        D8 --> D9["独立事实核验"]
        D9 -->|失败| D10["自动修复或人工编辑"]
        D10 --> D9
        D9 -->|通过| D11["版本固化 / DOCX 导出"]
    end
~~~

三类工作流共享检索服务、配置快照、模型网关和 WorkflowRun 轨迹，但各自保留独立的状态、
门禁和降级策略。

## 5. 配置版本、影子重建与发布

~~~mermaid
sequenceDiagram
    actor Admin as 管理员
    participant Web as 配置中心
    participant API as FastAPI
    participant DB as PostgreSQL
    participant Worker as Celery Worker
    participant Index as Qdrant

    Admin->>Web: 修改模型、路由或阈值
    Web->>API: 保存配置 + base_version_id
    API->>API: Schema、引用与能力校验
    API->>DB: 写入不可变 RuntimeConfigBundleV1
    API-->>Web: HOT / REPARSE_REQUIRED / REINDEX_REQUIRED

    Note over DB: 新任务立即固定新 config_version_id
    Note over Index: 当前 Publication 继续服务

    opt 需要重解析或重建索引
        Admin->>Web: 点击一键重建
        Web->>API: 创建影子代际
        API->>Worker: 下发重建任务
        Worker->>Index: 写入独立 Collection
        Worker->>DB: 写入页面、Chunk、向量状态
        API->>DB: 校验文档数、页面、Chunk 与向量
        Admin->>API: 发布新代际
        API->>DB: 原子切换 Publication
    end
~~~

Embedding 维度、模型签名或距离算法不同的向量不会写入同一 Collection。回滚不会修改旧记录，
而是复制历史配置并生成新的当前版本。

## 6. 数据追溯关系

~~~mermaid
flowchart LR
    SOURCE["SourceFile<br/>路径 + SHA-256"] --> DOC["Document<br/>案件 / 角色 / 版本"]
    DOC --> PAGE["Page<br/>页码 + 坐标 + page_id"]
    PAGE --> PARA["段落 / 标题"]
    PAGE --> TABLE["表格 JSON / HTML"]
    PAGE --> IMAGE["页面图 / 表格截图"]
    PAGE --> CHUNK["Chunk"]
    CHUNK --> TVEC["文本向量"]
    IMAGE --> VVEC["ColPali 多向量"]

    CONFIG["ConfigVersion"] --> JOB["IngestionJob"]
    JOB --> SOURCE
    JOB --> GEN["IndexGeneration"]
    GEN --> PUB["Publication"]

    CONFIG --> RUN["WorkflowRun"]
    PUB --> RUN
    RUN --> TRACE["节点轨迹 / 模型签名<br/>Token / 费用状态 / 引用"]
~~~

任何答案、审核意见或稿件都能追溯到配置版本、索引代际、页面证据和工作流节点。

## 7. 失败与降级策略

| 故障 | 系统行为 |
| --- | --- |
| Docling 或原生解析质量不足 | 升级为 OCR、区域重识别或可选 VLM |
| ColPali 必需页面失败 | 重试或进入人工审核，禁止发布为成功 |
| 文本 Embedding 不可用 | 保留本地中文词法召回 |
| Reranker 不可用 | 保留 RRF 融合排序 |
| DeepSeek 不可用 | QA 降级为本地抽取/拒答；审核保留规则；撰写保留门禁与模板路径 |
| 云端预算耗尽 | 停止新增云调用并记录原因 |
| 配置并发覆盖 | 通过 <code>base_version_id</code> 乐观锁拒绝保存 |
| 新索引不完整 | 保持旧 Publication，不执行切换 |

## 8. 安全边界

- 原始语料只读，所有转换结果写入独立产物目录；
- API Key 只读取允许的环境变量，Web 仅显示“已配置/未配置”；
- 参考材料被视为不可信数据，不执行文档内指令；
- 审核与撰写向模型发送证据前执行低价值附件过滤和个人信息脱敏；
- 风格参考不携带历史事实进入撰写模型，防止跨案件事实污染；
- 云端处理需要配置允许、任务授权和预算门禁同时满足。
